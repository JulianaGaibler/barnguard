# 3D

Stargazer draws 3D content next to 2D content. A {@link MeshNode} is a 3D node
with a geometry and a material. You add it to the same {@link SceneTree}
(`engine.tree`) that holds your 2D nodes, and a {@link CameraNode3D} views it.
Lights, glTF models, shadows, fog and pointer picking work on the same nodes.

Each frame the stage draws the 3D nodes first, with depth testing, and then
draws the 2D content on top. A stage with no 3D content runs only the 2D
pipeline. You need an engine to add nodes to. See [Engine setup](/guides/setup).

## Basic usage

This example draws a lit cube. It adds a mesh, a light and a camera to the tree:

```ts
import {
  CameraNode3D,
  DirectionalLight3D,
  MeshNode,
  createBoxGeometry,
  quat,
  quatFromAxisAngle,
} from '@src/stargazer'

const cube = new MeshNode(createBoxGeometry(1), {
  lit: true,
  pbr: true,
  color: [0.9, 0.3, 0.2, 1],
  metallicFactor: 0,
  roughnessFactor: 0.6,
})
cube.transform.setPosition(0, 0, -6)
engine.tree.add(cube)

const sun = new DirectionalLight3D({ intensity: 3 })
const tilt = quatFromAxisAngle(quat(), 1, 0, 0, -0.7)
sun.transform.setRotation(tilt.x, tilt.y, tilt.z, tilt.w)
engine.tree.add(sun)

const cam = new CameraNode3D()
cam.transform.setPosition(0, 1.5, 4)
engine.tree.add(cam)
```

The camera looks down its local `-z` axis, so it sees the cube 10 units in front
of it. The light shines down its own `-z` axis, tilted toward the ground. The
first 3D camera added to a stage becomes the current one. **Without a 3D camera,
the stage draws no 3D content.**

`metallicFactor` defaults to `1` for PBR materials, and a metal with nothing to
reflect looks dark, so this example sets it to `0`.

### Move and rotate nodes

Each 3D node has a `transform`, a {@link Transform3D} with a position, a
rotation quaternion and a scale. Set them with `setPosition(x, y, z)`,
`setRotation(x, y, z, w)` and `setScale(x, y, z)`. If you change the fields in
place instead, call `transform.markDirty()` afterward.

Use `add` to nest nodes. A child inherits its parent's world transform:

```ts
import { Node3D } from '@src/stargazer'

const pivot = new Node3D()
pivot.transform.setPosition(0, 0, -6)
engine.tree.add(pivot)
pivot.add(cube) // the cube moves with the pivot
```

A plain {@link Node3D} has only a transform, so it works as a group.

### Animate a node

`Node3D.tween` interpolates position and scale, rotates along the shortest arc
between rotations, and also takes `alpha`:

```ts
import { easings, quat, quatFromAxisAngle } from '@src/stargazer'

await cube.tween(
  {
    rotation: quatFromAxisAngle(quat(), 0, 1, 0, Math.PI),
    position: { x: 2, y: 0, z: -6 },
  },
  { duration: 1, easing: easings.inOutCubic },
)
```

The promise resolves when the tween ends. `quatFromAxisAngle` takes a
unit-length axis and an angle in radians.

### Load a glTF model

{@link loadGltf} fetches a `.glb` or `.gltf` file, builds a tree of nodes, and
decodes the textures before it resolves:

```ts
import { loadGltf } from '@src/stargazer'

const model = await loadGltf('/models/robot.glb')
model.transform.setPosition(0, 0, -6)
engine.tree.add(model)
```

The returned root is a `Node3D`. The model's materials use the PBR program, its
lights become light nodes, and its first animation plays in a loop. See
[glTF details](#gltf-details) for what the loader reads.

### Add lights

Lights are nodes, so they move, nest and animate like other nodes. There are
three kinds:

- {@link DirectionalLight3D} casts parallel rays along its local `-z` axis. Its
  position does not matter.
- {@link PointLight3D} shines in all directions from its position, with
  inverse-square falloff.
- {@link SpotLight3D} shines a cone along its local `-z` axis.

This example adds a warm point light:

```ts
import { PointLight3D } from '@src/stargazer'

const lamp = new PointLight3D({ color: [1, 0.8, 0.4], intensity: 5, range: 8 })
lamp.transform.setPosition(0, 2, -4)
engine.tree.add(lamp)
```

`range` fades the light to zero at that distance. The default `0` means no
limit. Light nodes affect PBR meshes. A scene with no light nodes uses one
built-in directional light. See [Lighting](#lighting) for the details.

### Cast shadows

Set `shadowEnabled` on a light to make it cast shadows. PBR meshes receive them:

```ts
const sun = new DirectionalLight3D({
  intensity: 3,
  shadowEnabled: true,
  shadowMaxDistance: 20,
})
```

`shadowMaxDistance` limits how much of the scene one directional shadow map
covers, which keeps nearby shadows sharp. See [Shadows](#shadows).

### Pick meshes with the pointer

Pointer events reach 3D nodes the same way they reach 2D nodes. Set `hitEnabled`
and assign a handler, or use `bindPointer`:

```ts
cube.hitEnabled = true
cube.onPointerDown = () => select(cube)
```

On a press, the input system tests the 2D content first, because it draws on
top. If nothing 2D is hit, it casts a ray from the current 3D camera and picks
the nearest mesh with `hitEnabled`. The test uses each mesh's bounding box, not
its triangles.

## Advanced usage

This section covers coordinates, how 2D and 3D share the tree, cameras,
materials, geometry, models, lights, shadows, fog, quality settings, picking,
HTML overlays and debugging.

### Coordinate conventions

The two spaces use different conventions:

- 2D is y-down, in world units the size of a CSS pixel at zoom 1.
- 3D is right-handed and y-up, in meters, like glTF. A camera looks down its
  local `-z` axis. Triangles wound counter-clockwise face the viewer, and back
  faces are culled.

The two spaces share no coordinates. All 3D content draws behind all 2D content,
so they never hide each other.

### 2D and 3D in one tree

2D and 3D nodes can be siblings, and you can nest one kind under the other.
Nesting controls lifecycle and grouping only. Destroying a parent destroys its
children, and visibility passes down the whole tree regardless of kind.

Nesting does not affect position. A node builds its world transform from its
nearest ancestor of the same kind, skipping nodes of the other kind and
`GroupNode`s in between. A `Node2D` under a `Node3D` ignores the 3D transform,
follows its nearest 2D ancestor, and draws on top of the 3D pass.

### Cameras and projection

A stage tracks one current 3D camera. The first {@link CameraNode3D} added
becomes current. Call [`makeCurrent()`](/module/camera/cameranode3d#makecurrent)
to switch to another one, and set `enabled = false` to take one out of use. When
the current camera is removed or disabled, the enabled camera with the highest
`priority` takes over. `engine.currentCamera3D` is `null` until you add a
camera.

The view is the inverse of the camera node's world transform, so parenting the
camera to a moving node makes it follow that node. These fields shape the
projection:

| Field            | Default | Meaning                                              |
| ---------------- | ------- | ---------------------------------------------------- |
| `fovY`           | `50`    | Vertical field of view, in degrees                   |
| `near`           | `0.1`   | Near clip distance                                   |
| `far`            | `1000`  | Far clip distance                                    |
| `focalDistance`  | `8`     | Depth that keeps its on-screen size across the blend |
| `projectionness` | `1`     | Blend from orthographic (`0`) to perspective (`1`)   |

The stage sets the aspect ratio from the canvas size every frame.

A camera blends continuously between orthographic and perspective projection. An
object at `focalDistance` keeps its on-screen size during the blend, so the
change does not look like a zoom.
[`animateProjection`](/module/camera/cameranode3d#animateprojection) tweens the
blend:

```ts
import { easings } from '@src/stargazer'

cam.focalDistance = 6
await cam.animateProjection(0, { duration: 0.8, easing: easings.inOutCubic })
```

The duration defaults to 0.5 seconds.

### Materials

A {@link MeshMaterial} uses one of two shader programs, both drawn in the same
pass:

- The flat program draws `{ lit, color }` with straight (not premultiplied)
  RGBA. A lit flat material is shaded by the built-in directional light and a
  constant ambient. It ignores light nodes and receives no shadows.
- The PBR program draws a material with `pbr: true`. It uses metallic-roughness
  shading with every light node. glTF materials set `pbr: true`.

PBR materials take optional textures (`baseColorTex`, `metalRoughTex`,
`normalTex`, `occlusionTex`, `emissiveTex`) and factors:

| Field                 | Default     | Meaning                                                |
| --------------------- | ----------- | ------------------------------------------------------ |
| `metallicFactor`      | `1`         | `0` for a non-metal, `1` for a metal                   |
| `roughnessFactor`     | `1`         | `0` for a mirror finish, `1` for fully rough           |
| `emissiveFactor`      | `[0, 0, 0]` | Light the surface gives off, linear RGB                |
| `occlusionStrength`   | `1`         | How much `occlusionTex` darkens ambient light          |
| `normalScale`         | `1`         | Strength of the normal map                             |
| `diffuseTransmission` | `0`         | Light passing through the surface, for thin leaves     |
| `toonSteps`           | off         | Bands the diffuse light into this many steps, from `2` |

Both programs read these fields:

| Field         | Default    | Meaning                                                       |
| ------------- | ---------- | ------------------------------------------------------------- |
| `alphaMode`   | `'OPAQUE'` | `'OPAQUE'`, `'MASK'` (cut out below `alphaCutoff`), `'BLEND'` |
| `alphaCutoff` | `0.5`      | Alpha below which a `MASK` material discards                  |
| `doubleSided` | `false`    | Draws back faces too                                          |
| `castShadow`  | `true`     | Whether the mesh casts into the shadow maps                   |

Every PBR field is optional, so a plain `{ lit, color }` stays valid. Set
`castShadow: false` for geometry that should look like an overlay, such as a
highlight lying on a surface. A `BLEND` mesh never casts.

An unlit flat material still takes a `baseColorTex`. The flat program draws it
unshaded, multiplied by `color`, and applies `alphaMode: 'MASK'` with a discard.
Use it for finished artwork, where shading would make two copies of the same
drawing at different angles look different.

`toonSteps` is for a scene drawn in flat color, where a smoothly shaded curve
would look out of place. Three or four steps keep a cylinder readable as a few
blocks of tone. Only diffuse light is banded. The specular highlight keeps its
smooth falloff, because a banded highlight looks like an error.

### Build geometry

A {@link MeshGeometry} is a plain object: positions, normals, optional `uvs` and
`tangents`, and a 16-bit or 32-bit index list. You can build one by hand and
pass it to `MeshNode`. These builders cover common shapes:

```ts
createBoxGeometry(size)
createQuadGeometry({ width, height, origin?, uvRect? })
createRoundedQuadGeometry({ width, height, radius, cornerSegments?, origin?, uvRect? })
createDiscGeometry({ radius, segments?, innerRadius?, startAngle?, sweepAngle? })
createPrismGeometry({ sides, radius, height, topRadius?, caps?, origin?, smooth? })
```

Quads lie in the XY plane and face `+z`, like a sheet held up to the camera.
Discs and prisms stand on the XZ plane with `+y` up, like an object on the
ground. Rotate the node to place them elsewhere.

`innerRadius` turns a disc into a ring, and `sweepAngle` leaves it open. One
builder covers a filled circle, a pie slice, a ring and an arc. Sweeps start at
`startAngle` (`0` is `+x`) and run clockwise in the XZ plane, which keeps the
winding counter-clockwise seen from `+y`.

`createPrismGeometry` covers both a low-poly marker and a smooth cylinder.
`sides` sets the outline: `3` is a triangular prism, and `48` looks like a
cylinder. By default each side face gets one flat normal, so the facets show.
With `smooth: true` the shading is continuous across the sides. `topRadius`
tapers the prism, and the normals tilt with the taper so a cone is lit
correctly.

For a panel with rounded corners, use `createRoundedQuadGeometry` rather than an
alpha cutout. The edge stays clean at any scale, and the material can stay
`'OPAQUE'`, so the mesh writes depth and casts a correctly shaped shadow.

### Textures from runtime artwork

{@link createTexture} builds the {@link MaterialTexture} that a texture slot
takes, from a canvas or an `ImageBitmap`. It is how art that did not come from a
glTF file gets onto a mesh, and it pairs with {@link rasterizeSvg}:

```ts
import {
  MeshNode,
  createQuadGeometry,
  createTexture,
  rasterizeSvg,
} from '@src/stargazer'

const canvas = await rasterizeSvg(svgText, { width: 512 })
const tex = await createTexture(canvas) // sRGB and mipmapped by default
const card = new MeshNode(createQuadGeometry({ width: 2, height: 1 }), {
  lit: false,
  color: [1, 1, 1, 1],
  baseColorTex: tex,
})
engine.tree.add(card)
```

The card shows the SVG unshaded, on a 2 by 1 meter quad facing `+z`.

See [Assets](/guides/assets) for the options.

### Draw order and transparency

Each frame the renderer draws the opaque and alpha-`MASK` meshes first, writing
depth. Within each program they draw nearest first, so the depth test rejects
what is hidden behind them. Then it draws `BLEND` meshes from back to front,
without writing depth.

A mesh's geometry can start as `null`, for example while a model downloads. The
renderer skips the mesh until its geometry is set and uploaded. After a GPU
context loss, buffers upload again from the geometry the mesh holds.

### glTF details

`loadGltf` reads these parts of a glTF file:

- Mesh geometry: `POSITION`, `NORMAL`, `TEXCOORD_0` and `TANGENT` of `TRIANGLES`
  primitives, with 16-bit or 32-bit indices and quantized attributes. It
  computes normals the file leaves out.
- The node tree, with TRS or matrix transforms.
- Metallic-roughness materials and their textures. Base color and emissive load
  as sRGB, the others as linear data, with mipmaps as the file's sampler asks.
- Alpha mode, double-sidedness, `KHR_materials_diffuse_transmission` and
  `KHR_materials_emissive_strength`.
- `KHR_lights_punctual` lights, as light nodes.
- TRS animations. The loader adds an {@link AnimationPlayer} for the first clip.

`KHR_materials_transmission` glass draws as a plain translucent blend, without
refraction. The loader does not read skinning, morph targets, a second UV set or
image-based lighting. For an unsupported extension it logs a warning once and
loads the model without it, even when the file lists the extension as required.

{@link parseGltf} is the synchronous core, for tests and custom loaders. It
builds the tree and attaches texture descriptors that hold the compressed image
bytes, but decodes no images and does no GPU work. `loadGltf` calls it and then
decodes the images with `createImageBitmap`.

### Animation

`loadGltf` reads a model's TRS keyframe animations into {@link AnimationClip}
objects. It adds an `AnimationPlayer` under the returned root that plays the
first clip in a loop. The player writes the transforms during the update pass,
before world matrices are computed, so animated nodes draw in their new pose in
the same frame.

```ts
import { AnimationPlayer, loadGltf } from '@src/stargazer'

const model = await loadGltf('/models/bird.glb') // already animating
const player = model.children.find(
  (n) => n instanceof AnimationPlayer,
) as AnimationPlayer
player.speed = 0.5
player.pause()
```

`speed`, `looping`, `playing` and `time` (the playhead in seconds) are public
fields. `resume(fromStart?)` continues playback. `LINEAR` and `STEP`
interpolation are exact. `CUBICSPLINE` is treated as linear between the keyframe
values. Only the first clip in a file gets a player.

### Lighting

The renderer reads each light's world position and its local `-z` axis every
frame, so a light nested under a moving node follows it. The PBR program shades
with up to eight light nodes and ignores any beyond that.

All lights take `color` (linear RGB, default white) and `intensity` (default
`1`). `PointLight3D` and `SpotLight3D` take `range`. A spot light also takes
`innerConeAngle` (default `0`) and `outerConeAngle` (default `π / 4`), both
half-angles in radians: full brightness inside the inner cone, dark outside the
outer cone.

PBR shading is metallic-roughness Cook-Torrance GGX, plus a constant ambient
term. There is no image-based lighting, so a pure metal with no light to reflect
looks dark. glTF point and spot intensities are physical units (candela), so
imported lights can look faint. Raise their `intensity` if they do.

For darkening in contact seams and creases, turn on ambient occlusion with
`engine.ambientOcclusion.enabled = true`. See
[Ambient occlusion](/guides/ambient-occlusion).

### Shadows

All three light types can cast. Opaque and alpha-`MASK` meshes cast, and PBR
meshes receive. A `MASK` mesh casts the shape of its whole geometry, not of its
cutout.

These light fields tune shadows:

| Field               | Default                  | Meaning                                          |
| ------------------- | ------------------------ | ------------------------------------------------ |
| `shadowEnabled`     | `false`                  | Whether the light casts                          |
| `shadowBias`        | `0.0025`                 | Depth offset that moves the test off the surface |
| `shadowNormalBias`  | `1`, `2` for directional | Offset along the surface normal, in world units  |
| `shadowOpacity`     | `1`                      | `1` is fully dark, lower values lighten it       |
| `shadowMaxDistance` | `0` (fit to casters)     | Directional only: largest area the map covers    |

Too little bias causes shadow acne, where a surface shadows itself in stripes.
Too much detaches a shadow from its caster. The defaults suit meter-scale
scenes. Shadows are filtered with a small PCF kernel (several depth samples
averaged) for soft edges.

A directional shadow map fits itself to the bounds of all casters. That is sharp
for a compact scene, but a large ground plane spreads the map thin and blurs
nearby shadows. A positive `shadowMaxDistance` caps the fitted area and keeps
resolution on the near scene.

Up to four directional and spot lights cast at once, one shadow map each. Only
one point light casts, because its map is a cube map and WebGL2 has no cube map
arrays.

The shadow maps render again only when something they depend on changes: a
caster moves or changes geometry, a casting light moves or changes its reach, a
mesh or light is added, removed or hidden, or the map size changes. A still
scene renders no shadow passes and reuses the maps.

### Fog

`engine.fog` is a live {@link Fog} object that blends every 3D surface toward a
color by its distance from the camera. Use it to fade distant geometry into a
horizon or to hide the far clip plane. It applies to flat and PBR meshes and is
off until you enable it:

```ts
import { createEngineHost } from '@src/stargazer'

const host = createEngineHost({
  canvas,
  fog: { enabled: true, color: [0.6, 0.7, 0.85], density: 0.05 },
})

host.engine.fog.mode = 'linear' // switch models at runtime
host.engine.fog.start = 8 // clear up close
host.engine.fog.end = 40 // solid fog beyond here
```

These fields control it:

| Field     | Default            | Meaning                                                                                 |
| --------- | ------------------ | --------------------------------------------------------------------------------------- |
| `enabled` | `false`            | Whether fog applies                                                                     |
| `mode`    | `'exp'`            | `'exp'` fades as `1 - exp(-density * distance)`, `'linear'` ramps from `start` to `end` |
| `color`   | `[0.7, 0.75, 0.8]` | Display-space (gamma) RGB, `0` to `1`                                                   |
| `density` | `0.05`             | `exp` falloff rate. Larger values fade sooner                                           |
| `start`   | `0`                | `linear` distance where fog begins                                                      |
| `end`     | `50`               | `linear` distance of solid fog, kept above `start`                                      |

`'exp'` fog never reaches full strength, so nothing cuts off at a fixed
distance. `'linear'` is easier to control for a bounded scene. The color is
applied after tone mapping, so it shows as the exact color you set.

Fog is a color blend inside the mesh shaders, with no extra passes. It tints
color only and leaves alpha unchanged, so transparent surfaces still blend
correctly. The debug views "unshaded" and "normals" skip it. Screen-space
effects such as a vignette run over the whole frame instead. See
[Post-processing](/guides/post-processing).

### Render quality

`engine.quality` is a live {@link RenderQuality} object. Set its starting values
when you create the host, and change them at any time. The renderer uses a
change on the next frame:

```ts
const host = createEngineHost({
  canvas,
  quality: { shadowMapSize: 2048, anisotropy: 8 },
})

host.engine.quality.meshShadowsEnabled = false
```

These are the 3D settings:

| Field                | Default | Meaning                                                                  |
| -------------------- | ------- | ------------------------------------------------------------------------ |
| `shadowMapSize`      | `1024`  | Edge length of every shadow map, snapped to 256, 512, 1024, 2048 or 4096 |
| `meshShadowsEnabled` | `true`  | Turns all shadow passes off when false. Lights still shade               |
| `anisotropy`         | `8`     | Anisotropic filtering for mipmapped textures, `1` (off) to `16`          |
| `shadowSoftness`     | `4`     | PCF samples per lookup, snapped to 1, 4, 9 or 16                         |
| `adaptive`           | `true`  | Lets the engine lower quality when the GPU cannot keep up                |

A larger shadow map is sharper and costs more memory and fill. More PCF samples
soften shadow edges. With `adaptive` on, the engine lowers ambient occlusion,
MSAA, shadow softness, the render scale and finally shadows, one step at a time.
See [Engine setup](/guides/setup).

### Pick by hand

[`screenToRay(ndcX, ndcY)`](/module/camera/cameranode3d#screentoray) builds a
world-space ray from a normalized device coordinate, where `x` and `y` run from
`-1` to `1` and `y` points up. {@link raycastWorld3D} returns the nearest
visible mesh the ray hits and the distance to it:

```ts
import { raycastWorld3D } from '@src/stargazer'

const ray = engine.currentCamera3D!.screenToRay(ndcX, ndcY)
const hit = raycastWorld3D(engine.tree, ray)
if (hit) select(hit.node)
```

An optional third argument filters the meshes it tests. Like pointer picking, it
tests bounding boxes.

### Releases outside the pressed mesh

The node a pointer goes down on captures it, so `onPointerUp` arrives there
wherever the release lands. A 3D button that should not fire when the press is
dragged off it has to check again on release.
[`pick3D(cssX, cssY)`](/module/input/inputsystem#pick3d) runs the same pick as
the press, including under the debug fly camera:

```ts
mesh.onPointerUp = (e) => {
  const under = e.stage.input?.pick3D(e.pointer.screen.x, e.pointer.screen.y)
  if (under === mesh) fire()
}
```

For 2D nodes, {@link ButtonBehavior} does this for you.

### HTML pinned to a 3D node

The {@link domAnchor3d} Svelte action, or `engine.dom.attachWorld3d`, moves an
HTML element to a 3D node's position on screen every frame. It hides the element
when the node is behind the camera:

```svelte
<div
  use:domAnchor3d={{ engine, node: cube, camera: cam, scaleWithDistance: true }}
>
  <button onclick={fire}>Launch</button>
</div>
```

By default the element stays upright on screen. `scaleWithDistance` shrinks it
with depth. `orient: true` tilts it with the node's surface through a CSS
`matrix3d`, and stays aligned with the meshes across the
orthographic-to-perspective blend. With `orient`, `pxPerUnit` (default `200`)
sets element pixels per world unit, and `backfaceCull` (default `true`) hides
the element when it faces away. The element is never hidden behind meshes. See
[HTML overlays](/guides/html-overlays) for the container setup.

[`worldToScreen(x, y, z, cssW, cssH)`](/module/camera/cameranode3d#worldtoscreen)
is the projection underneath. It returns CSS-pixel coordinates and a `behind`
flag.

### Debugging 3D

The debug HUD (`?debug=hud`, or press `Y`) covers the 3D world:

- `V` switches to a free 3D fly camera. A/D strafe, W/S move forward and back,
  E/Q move up and down, and the arrow keys turn. Click the canvas for mouse look
  and press Esc to release it. Shift sprints and the scroll wheel sets the
  speed.
- `O` outlines node bounds, including mesh bounding boxes.
- The Rendering panel's render mode adds 3D views when the scene has 3D content:
  wireframe, unshaded albedo, world normals, and raw ambient occlusion.
- The Quality panel holds the shadow, ambient occlusion and texture filtering
  settings.
- The texture inspector has a "3D models" source that lists every loaded
  material texture with its role.
- `P` freezes updates and tweens while rendering and the debug camera keep
  running.

The Scene panel shows 2D, 3D and group nodes in one tree. See
[Debugging](/guides/debugging).

### Known limitations

The 3D renderer has these limits:

- All 3D content draws behind all 2D content. The 3D pass runs at the start of
  the main pass, before the recorded 2D layers, whatever order the nodes are in.
  To show 2D behind 3D, leave that area of the 2D content empty.
- 2D content cannot be placed inside the 3D scene, for example mapped onto a
  mesh.
- Lighting is analytic: light nodes plus a constant ambient. Metals and glass
  have nothing to reflect and look flat or dark. Ambient occlusion adds contact
  darkening, but by default it only darkens the ambient term.
- Flat materials use only the built-in light and receive no shadows.
- `KHR_materials_transmission` glass has no refraction, clearcoat or blurred
  background.
- Without `TANGENT` data, normal mapping derives tangents from screen-space
  derivatives.
- glTF skinning, morph targets and second UV sets are not read, `CUBICSPLINE`
  animation is approximated as linear, and only the first animation clip plays.
