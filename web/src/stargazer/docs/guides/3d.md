# 3D

`Node2D` (2D) and `Node3D` (3D) share a non-spatial base (`Node`) for children, behaviors,
lifecycle, abort, and the tween/wait/loop helpers, and both live under a single `SceneTree`
(`engine.tree`). Each frame the renderer walks that one tree and buckets by `node.kind`: the 3D
pass draws first with depth testing, then the 2D painter-order pass composites on top. A stage with
no 3D content runs the 2D pipeline unchanged.

## Coordinate conventions

- **2D** is y-down, in CSS-pixel-like world units. Unchanged from a 2D-only engine.
- **3D** is right-handed, y-up, in meters, matching glTF. The camera looks down its local `-z`.
  Triangle winding is CCW-front; back faces are culled.

The two spaces don't share coordinates. 3D content renders behind 2D content by construction, so
they don't occlude each other; a 3D quad and a 2D node are never in the same pass.

## One tree, but nesting is not depth

2D and 3D nodes can be siblings, and you may nest one kind under the other. That nesting is for
**lifecycle and logical grouping only** — destroying a parent destroys the child, and visibility
inherits down the whole tree regardless of kind. It is **not** spatial: a node composes its world
transform from its nearest _same-kind_ ancestor, skipping any different-kind (or `GroupNode`)
ancestors in between. So a `Node2D` parented under a `Node3D` doesn't inherit the 3D transform; it
locks to its nearest 2D ancestor's screen space and draws on top of the whole 3D pass, never
occluded by it. To place 2D content _inside_ the 3D scene (occluded, perspective-correct), use the
`Viewport2DNode` bridge (see [2D content in 3D](#2d-content-in-3d)).

## The 3D world and camera

Add 3D nodes to the tree (`engine.tree`) and drive the 3D view with a `CameraNode3D` you add and
`makeCurrent()` (cameras are never auto-created; `engine.currentCamera3D` is `null` until you add
one). The view is the inverse of the node's world pose, so parenting the camera drives it:

```ts
import { MeshNode, CameraNode3D, createBoxGeometry } from '@src/stargazer'

const cube = new MeshNode(createBoxGeometry(1), {
  lit: true,
  color: [0.9, 0.3, 0.2, 1],
})
cube.transform.setPosition(0, 0, -6)
engine.tree.add(cube)

const cam = new CameraNode3D()
cam.transform.setPosition(0, 1.5, 4)
engine.tree.add(cam)
cam.makeCurrent()
```

`Node3D.transform` is a `Transform3D`: a position `Vec3`, a rotation `Quat`, and a per-axis scale
`Vec3`. Set them through `setPosition` / `setRotation` / `setScale` (or mutate in place and call
`transform.markDirty()`). Nest nodes with `node.add(child)`; children inherit the parent's world
transform.

Animate with `Node3D.tween`, which lerps position and scale and slerps rotation:

```ts
import { quatFromAxisAngle, quat } from '@src/stargazer'

await cube.tween(
  {
    rotation: quatFromAxisAngle(quat(), 0, 1, 0, Math.PI),
    position: { x: 2, y: 0, z: -6 },
  },
  { duration: 1, easing: easings.inOutCubic },
)
```

## Orthographic <-> perspective

`CameraNode3D` blends continuously between orthographic and perspective rather than switching. Its
`projectionness` runs from `0` (ortho) to `1` (perspective). `focalDistance` anchors the blend: an
object at that depth keeps its on-screen size across the transition, so it doesn't appear to zoom.

```ts
cam.focalDistance = 6
// Ease from perspective to a flat orthographic look.
await cam.animateProjection(0, { duration: 0.8, easing: easings.inOutCubic })
```

`fovY`, `near`, `far`, and the viewport aspect (set by the stage on resize) shape the projection.

## Meshes and materials

`MeshNode` holds a `MeshGeometry` (separate position, normal, and optional uv/tangent arrays plus a
triangle index list, 16- or 32-bit) and a `MeshMaterial`. A material is either **flat** — `{ lit,
color }`, straight RGBA, shaded by one directional light plus ambient (or unlit) — or **PBR**: set
`pbr: true` (glTF materials do automatically) to route it through the metallic-roughness program.
PBR materials add optional texture slots (`baseColorTex`, `metalRoughTex`, `normalTex`,
`occlusionTex`, `emissiveTex`), scalar factors (`metallicFactor`, `roughnessFactor`,
`emissiveFactor`, `occlusionStrength`, `normalScale`), `alphaMode` (`'OPAQUE'`/`'MASK'`/`'BLEND'`)
with `alphaCutoff`, `doubleSided`, and a `diffuseTransmission` term for translucent surfaces. Every
PBR field is optional, so a plain `{ lit, color }` stays valid. `createBoxGeometry(size)` builds a
flat-shaded cube for quick tests.

Flat and PBR meshes are drawn by separate shader programs in one pass; each frame the renderer draws
the opaque + alpha-`MASK` meshes first (depth-writing), then `BLEND` meshes back-to-front with
depth-write off. `doubleSided` materials disable back-face culling.

Geometry can start `null` and be filled in later (a model still downloading); the pass skips a mesh
until its geometry is set and uploaded. GPU buffers re-upload from the retained CPU geometry after a
context loss.

## Loading glTF

`loadGltf(url)` fetches a `.glb` or `.gltf` (external or data-URI buffers), builds the scene root
`Node3D`, and decodes its textures before resolving:

```ts
import { loadGltf } from '@src/stargazer'

const model = await loadGltf('/models/robot.glb')
engine.tree.add(model)
```

It reads mesh geometry (POSITION, NORMAL, TEXCOORD_0, TANGENT, `TRIANGLES`, 16-/32-bit and quantized
indices/attributes), the node hierarchy with TRS or matrix transforms, metallic-roughness materials
with their textures (base-color and emissive as sRGB, normal/metallic-roughness/occlusion as linear,
mipmapped per the glTF sampler), alpha mode, double-sidedness,
`KHR_materials_diffuse_transmission`, `KHR_lights_punctual` (imported as [light nodes](#lighting)),
and TRS animations (played by an auto-attached [`AnimationPlayer`](#animation)). Missing normals are
computed. `KHR_materials_transmission` glass degrades to a translucent blend (no refraction).
Skinning, morph targets, a second UV set, and image-based lighting are not read; an unsupported
`extensionsRequired` warns rather than failing the load.

`parseGltf(doc, buffers)` is the pure, synchronous core (used by tests): it builds the tree and
attaches texture descriptors carrying the images' compressed bytes, but does no image decode or GPU
work — `loadGltf` wraps it with the `createImageBitmap` decode pass.

## Lighting

Lights are scene-tree nodes, so they transform, parent, and animate like anything else. Add
`DirectionalLight3D`, `PointLight3D`, or `SpotLight3D`; the renderer reads each light's world
position and its local −Z axis (world-space) each frame, so a light parented to a moving node
tracks it.

```ts
import { DirectionalLight3D, PointLight3D } from '@src/stargazer'

const sun = new DirectionalLight3D({ color: [1, 0.96, 0.9], intensity: 3 })
sun.transform.setRotation(quatFromAxisAngle(quat(), 1, 0, 0, -0.7))
engine.tree.add(sun)

const lamp = new PointLight3D({ color: [1, 0.8, 0.4], intensity: 5, range: 8 })
lamp.transform.setPosition(0, 2, -4)
engine.tree.add(lamp)
```

`DirectionalLight3D` casts parallel rays (position irrelevant). `PointLight3D` radiates from its
world position with inverse-square falloff; `range` (default `0` = unbounded) windows it to zero at
that distance. `SpotLight3D` adds `innerConeAngle`/`outerConeAngle` (radians). A scene with **no**
light nodes falls back to a single built-in directional light; ambient always applies. glTF punctual
intensity is physical (candela/lux) and can read dim without image-based lighting — raise light
`intensity` if imported point/spot lights look faint. Lighting is metallic-roughness Cook-Torrance
GGX; there is no IBL, so pure metals with no light to reflect appear dark.

## Shadows

Set `shadowEnabled` on a light to make it cast. All three light types cast; PBR meshes receive
(flat `{ lit, color }` meshes don't). Casters are the opaque and alpha-`MASK` meshes — `MASK`
materials cast through their cutout, so foliage casts leaf shapes.

```ts
const sun = new DirectionalLight3D({
  intensity: 3,
  shadowEnabled: true,
  shadowMaxDistance: 20,
})
sun.transform.setRotation(quatFromAxisAngle(quat(), 1, 0.3, 0, -0.9))
engine.tree.add(sun)
```

`shadowBias` and `shadowNormalBias` control acne (a surface shadowing itself) versus peter-panning
(a shadow detaching from its caster); the defaults suit meter-scale scenes, and directional lights
use a larger normal bias. `shadowOpacity` lifts a shadow toward fully lit. Shadows are filtered with
a small PCF kernel for soft edges.

Directional shadows fit their map to the shadow casters' bounds. That is sharp for a compact scene,
but a large ground plane spreads the map thin and pixelates nearby shadows — set
`shadowMaxDistance` to cap the fitted radius and hold resolution on the near scene.

Two limits: any number of directional and spot lights cast (up to four maps at once), but only one
point light casts (its map is a depth cubemap, and WebGL2 has no cube-map arrays); and the flat
program is unshadowed.

## Fog

`engine.fog` is a live `Fog` object the renderer reads each frame — cheap distance fog that blends
every 3D surface toward a color by how far it sits from the camera. Use it to fade distant geometry
into a horizon, cue depth, or hide the far clip plane. It applies to both PBR and flat meshes (and
the textured `Viewport2DNode` quad); it is off until `enabled`.

```ts
const engine = new Engine({
  fog: { enabled: true, color: [0.6, 0.7, 0.85], density: 0.05 },
})

engine.fog.mode = 'linear' // switch models at runtime
engine.fog.start = 8 // clear up close…
engine.fog.end = 40 // …solid fog beyond here
```

- `color` — display-space (gamma) rgb in `0..1`, applied after tone-mapping so it reads as set.
- `mode` — `'exp'` (default) fades as `1 - exp(-density·distance)`, so nothing ever hard-clips;
  `'linear'` ramps from clear at `start` to solid at `end`, which is easier to art-direct.
- `density` — `exp` falloff rate; larger fades sooner.
- `start` / `end` — `linear` near/far distances (`end` is kept strictly beyond `start`).

Fog is a per-fragment color blend with no extra passes, so it is effectively free. It tints rgb only
and leaves alpha untouched, so transparent surfaces still composite correctly. Debug shader views
(unshaded, normals) skip it.

Fog lives in the 3D pass by design — it needs per-surface depth and must interleave with the
depth-sorted transparent draws. Screen-space image effects (vignette, chromatic aberration, blur)
instead run over the whole composited frame; see [Post-processing](/guides/post-processing).

## Render quality

`engine.quality` is a live `RenderQuality` object the renderer reads each frame. Set its defaults at
construction and change them at runtime; the renderer picks up a change on the next frame.

```ts
const engine = new Engine({
  quality: { shadowMapSize: 2048, anisotropy: 8 },
})

engine.quality.shadowsEnabled = false // e.g. on a low-power device
```

- `shadowMapSize` — edge length of every shadow map, snapped to a supported size (256–4096).
  Larger is sharper and costs more memory and fill.
- `shadowsEnabled` — turn the whole shadow pass off. Lights still shade; nothing is occluded.
- `anisotropy` — anisotropic filtering for mipmapped textures, clamped to 1–16 (1 = off). Sharpens
  textures viewed at grazing angles.
- `shadowSoftness` — PCF tap count (1/4/9/16); more taps soften shadow edges.

The debug HUD's Rendering panel exposes all four as live overrides under the 3D section, alongside a
Textures inspector source (`3D models`) that lists each loaded material texture with its role.

## Animation

`loadGltf` reads a model's TRS keyframe animations into `AnimationClip`s and attaches an
`AnimationPlayer` (a `Node3D`) under the returned root, auto-playing the first clip looped. Because
the player writes through the transform setters during the update pass — before the frame's
world-matrix pass — animated nodes render in their new pose the same frame.

```ts
import { AnimationPlayer } from '@src/stargazer'

const model = await loadGltf('/models/bird.glb') // already animating
const player = model.children.find(
  (n) => n instanceof AnimationPlayer,
) as AnimationPlayer
player.speed = 0.5
player.pause()
```

`LINEAR` and `STEP` interpolation are exact; `CUBICSPLINE` is approximated as linear over the value
keyframes. Skinned and morph-target animation are not supported.

## 2D content in 3D

`Viewport2DNode` renders a 2D scene to a texture and shows it on a transformable quad in the 3D
world. Build the 2D content under its `scene.root` as for any stage:

```ts
import { Viewport2DNode, ShapeNode } from '@src/stargazer'

const panel = new Viewport2DNode({ width: 512, height: 256 })
panel.scene.root.add(
  new ShapeNode({
    geometry: { kind: 'rect', width: 512, height: 256 },
    fill: '#123',
  }),
)
panel.transform.setPosition(0, 1, -3)
engine.tree.add(panel)
```

The quad starts scaled to the surface aspect (width:height) so 2D pixels aren't stretched; override
`transform.scale` to resize. The content is a raster snapshot at the surface resolution — raise
`width`/`height` for sharper results under steep or close views.

## Picking and pointer input

Pointer events dispatch to 3D nodes like 2D ones: set `hitEnabled` and assign handlers (or use
`bindPointer`), and the input system fires `onPointerDown/Move/Up/Cancel`. On a press it hit-tests
the 2D scene first (the 2D layers composite on top, so they win), then ray-picks the 3D world:

```ts
const cube = new MeshNode(geometry, material)
cube.hitEnabled = true
cube.onPointerDown = () => select(cube)
engine.tree.add(cube)
```

For manual picking, `CameraNode3D.screenToRay(ndcX, ndcY)` builds a world-space ray from a normalized
device coordinate (`[-1, 1]`, y up), and `raycastWorld3D(world, ray, filter?)` returns the nearest
struck `MeshNode` and its distance (bounds-level precision):

```ts
import { raycastWorld3D } from '@src/stargazer'

const ray = engine.currentCamera3D!.screenToRay(ndcX, ndcY)
const hit = raycastWorld3D(engine.tree, ray)
if (hit) select(hit.node)
```

## HTML pinned to a 3D node

`domAnchor3d` (or `engine.dom.attachWorld3d`) tracks an HTML element to a 3D node's projected screen
position each frame, hiding it when the node passes behind the camera. Position-only, so the element
stays screen-upright; pass `scaleWithDistance` to shrink it with depth.

```svelte
<div
  use:domAnchor3d={{ engine, node: cube, camera: cam, scaleWithDistance: true }}
>
  <button onclick={fire}>Launch</button>
</div>
```

`CameraNode3D.worldToScreen(x, y, z, cssW, cssH)` is the underlying projection: CSS-pixel coords plus a
`behind` flag. The element must sit in a container overlaying the canvas.

Pass `orient: true` to glue the element to the node's surface instead — it inherits the node's 3D
orientation and foreshortening via CSS `matrix3d`. The element is reparented into an engine-managed
layer over the canvas and carries the camera's full `viewProjection` baked into its matrix, so it
stays flush with the meshes across the entire ortho⇄perspective transition (parallel at the
orthographic end, foreshortened at the perspective end — CSS performs the perspective divide from
the baked matrix's w-row). `pxPerUnit` (default 200) sets how many element pixels map to one world
unit; `backfaceCull` (default true) hides it when its front turns away. Orient mode doesn't
depth-occlude against meshes.

## Debugging 3D

The debug HUD (`?debug=hud`, or press `Y`) covers the 3D world. A **Camera** dropdown picks what
drives the view: `Active` (default, the game cameras), `2D debug` (free pan/zoom, hotkey `C`), or
`3D debug` (free fly, hotkey `V`). The grid, outlines, and camera pad follow the selected mode, so
the 2D screen grid and the 3D ground grid never draw together. The 3D fly camera moves with WASD
strafe, E/Q up/down, forward/back, and arrows look (the pad's bottom corners dolly forward/back);
the game camera's frustum draws while it's active. `O` outlines mesh AABBs and `Viewport2DNode` quads.

A **3D render** dropdown (shown when the scene has 3D content) picks the mesh view: `Normal`
(shaded), `Wireframe` (triangle edges over the shaded fill, hidden-line-removed), `Unshaded` (flat
albedo, no lighting), or `Normals` (rgb = world normal). Unshaded and Normals are a `u_debugMode`
branch in the mesh shader; Wireframe draws depth-tested edges through the 3D line renderer.

The Scene panel shows the **one** unified tree (2D, 3D, and group nodes together, class-colored;
a `Viewport2DNode`'s embedded 2D scene nests under it), and selecting any node outlines it in its
own space. The Rendering/Camera panels show 3D draw counts and the camera pose/projection; the Rendering
panel's 3D section carries the live [render-quality](#render-quality) overrides. The Textures
inspector has a **Source** dropdown listing the screen and each `Viewport2DNode` (each render
target keeps its own atlas + glyph label-page), plus a `3D models` source that lists every loaded
material texture with its role (base color, normal, …). `P` pauses (engine-managed
`onUpdate`/`onFixedStep`/tweens freeze; rendering and the debug camera keep running).

## Known limitations

- **Z-order:** all 3D renders behind all 2D. Interleaving (3D between two 2D layers) is not
  available.
- **2D-in-3D is display-only:** pointer input does not route into a `Viewport2DNode`'s embedded 2D
  tree, and its content is a resolution-bound raster.
- **Cost:** each `Viewport2DNode` is a separate offscreen render; use them sparingly. Its GPU
  resources release when the stage is disposed.
- **No image-based lighting:** lighting is analytic (punctual lights + a constant ambient), so
  metals and glass have nothing to reflect and look flat/dark.
- **Shadows** cast from any number of directional and spot lights but only one point light, and
  fall on PBR meshes only (see [Shadows](#shadows)).
- **Glass:** `KHR_materials_transmission` renders as a plain translucent blend — no screen-space
  refraction, clearcoat, or roughness-blurred background.
- **Normal matrix** is the inverse-transpose upper 3×3, so non-uniform scale is handled correctly;
  tangent-space normal mapping falls back to screen-space derivatives when a mesh lacks TANGENT.
- **glTF gaps:** no skinning, morph targets, second UV set, or `CUBICSPLINE` (approximated linear).
